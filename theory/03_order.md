### ORDER BY

Без `ORDER BY` база не гарантирует никакого порядка строк, даже если сейчас они идут «как надо». Если порядок важен, задавайте его явно:

```
SELECT ... FROM ... [WHERE ...] ORDER BY <столбец> [ASC | DESC];
```

- `ASC` — по возрастанию (по умолчанию, можно не писать);
- `DESC` — по убыванию.

```sql
SELECT name, price FROM products ORDER BY price;
```

### Сортировка по нескольким столбцам

Столбцы перечисляются через запятую. Второй столбец используется, только когда значения первого совпадают. Направление задаётся для каждого столбца отдельно:

```sql
SELECT category, name, price
FROM products
ORDER BY category, price DESC;
```

Здесь товары сгруппированы по категориям по алфавиту, а внутри категории идут от дорогих к дешёвым.

Сортировать можно и по выражению, и по псевдониму из `SELECT`:

```sql
SELECT first_name || ' ' || last_name AS full_name, salary
FROM employees
ORDER BY full_name;
```

### NULL при сортировке

В SQLite значения `NULL` при сортировке по возрастанию идут первыми, по убыванию — последними. В других СУБД может быть иначе. Явно указать место можно через `NULLS FIRST` или `NULLS LAST`.

### LIMIT и OFFSET

`LIMIT n` оставляет первые `n` строк результата, `OFFSET m` пропускает первые `m`. Так делают постраничный вывод:

```sql
SELECT name, price
FROM products
ORDER BY price
LIMIT 3 OFFSET 3;
```

Это «вторая страница» товаров по 3 штуки, от дешёвых к дорогим.

> `LIMIT` без `ORDER BY` возвращает «какие-то» n строк. Если при сортировке есть одинаковые значения, добавьте ещё один столбец, чтобы результат был однозначным.

### Порядок частей запроса

```
SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ... OFFSET ...
```

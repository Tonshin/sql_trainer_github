Агрегатные функции сворачивают много строк в одно значение.

| Функция | Что считает |
|---|---|
| `COUNT(*)` | количество строк |
| `COUNT(столбец)` | количество значений, **не равных NULL** |
| `COUNT(DISTINCT столбец)` | количество разных значений |
| `SUM`, `AVG` | сумма и среднее |
| `MIN`, `MAX` | минимум и максимум |

```sql
SELECT COUNT(*)                      AS all_rows,
       COUNT(email)                  AS with_email,
       COUNT(DISTINCT department_id) AS departments
FROM employees;
```

Сравните первые два числа: `COUNT(email)` не считает строки, где email не указан.

### GROUP BY: агрегаты по группам

`GROUP BY` разбивает строки на группы с одинаковым значением столбца и считает агрегат отдельно для каждой группы:

```sql
SELECT category,
       COUNT(*)   AS products,
       MIN(price) AS cheapest,
       MAX(price) AS most_expensive
FROM products
GROUP BY category;
```

**Главное правило:** в `SELECT` при группировке можно писать только столбцы из `GROUP BY` и агрегатные функции. Остальные столбцы не имеют одного значения на группу. SQLite такой запрос выполнит и вернёт значение из случайной строки, а PostgreSQL выдаст ошибку.

Строки, где столбец группировки равен `NULL`, попадают в одну общую группу.

### WHERE или HAVING

- `WHERE` фильтрует **строки до** группировки;
- `HAVING` фильтрует **группы после** неё и может использовать агрегаты.

```sql
SELECT employee_id, COUNT(*) AS orders_count
FROM orders
WHERE status <> 'cancelled'
GROUP BY employee_id
HAVING COUNT(*) >= 4;
```

Здесь отменённые заказы отброшены ещё до подсчёта, а затем остались только сотрудники, у которых хотя бы 4 заказа.

### В каком порядке выполняется запрос

Пишем в одном порядке, а база выполняет в другом:

1. `FROM` — берём таблицу;
2. `WHERE` — фильтруем строки;
3. `GROUP BY` — группируем;
4. `HAVING` — фильтруем группы;
5. `SELECT` — вычисляем столбцы;
6. `ORDER BY` — сортируем;
7. `LIMIT` — обрезаем.

Поэтому в `WHERE` нельзя использовать агрегаты: на этом шаге групп ещё нет.
